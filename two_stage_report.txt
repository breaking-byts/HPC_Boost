DATASET
Step 1: Collection of Benign Dataset
Before simulating malware attacks, it's essential to have a baseline dataset consisting of benign
activities. This dataset typically represents normal operations without any malicious intent.
Here's how this step might be carried out:
1. Data Selection: Identify and gather a diverse set of benign activities or processes. This could
include common user applications, system processes, and other legitimate software.
2. Data Gathering: Collect data while these benign processes are running. This data can
include various HPC events.
Step 2: Simulating Malware Attacks
Now, the focus shifts to simulating malware attacks on top of the benign dataset. This step
involves executing malware programs and observing their behavior under different conditions:
1. Program Execution: Run the malware programs on different CPU cores. This step involves
parallelizing the execution of malware to observe how they interact with system resources when
executed concurrently.
2. Timing Attacks: Introduce time-based attacks by triggering malware at specific time points
during the runtime of benign processes. This step aims to capture the effect of malware
interference at different stages of normal system operation.
3. Data Collection: Record various metrics during the execution of malware attacks, similar to
the benign dataset collection. This includes HPC events. Additionally, note the timestamp of
each attack to correlate it with the runtime of benign processes.
Step 3: Dataset Expansion
To create a diverse and comprehensive dataset, it's crucial to explore various permutations of
core allocation and malware execution timings. This step involves systematically varying these
parameters to capture a wide range of scenarios:
1. Core Allocation: Execute malware on different CPU cores or combinations of cores. This
helps understand how malware behavior differs based on resource allocation.
2. Malware Timing: Vary the timing of malware attacks within the runtime of benign processes.
This includes early attacks, late attacks, and attacks at intermediate stages.

3. Dataset Size: Collect sufficient data to ensure statistical significance. The dataset size
mentioned (1 GB) indicates a substantial amount of data collection to cover diverse scenarios
adequately which will be truncated.

Overview
In this approach we divide our malware detection task into two stages. The first stage is a
continuous prediction model, that predicts the HPC event values based on 10 prior values.
Then, it compares these predictions with the actual values and flags the region in the actual
data that appear to be suspicious. This is done by training the model on bening datasets. The
comparison between predicted values and original values is made using cosine similarity score,
and a score less than a threshold of 0.3 is flagged. For inference, data prior and post to this flag
checkpoint is saved and sent to stage 2.
In the stage 2, we infer 2 things from the flagged dataset : whether the flagged window is
malicious or not, and if yes, on which core is the malware running. This is done using a 5 class
classification method.
The reason to do this to save some time for the users. The main malware prediction only
happens in the flagged region, rather than at all times.
